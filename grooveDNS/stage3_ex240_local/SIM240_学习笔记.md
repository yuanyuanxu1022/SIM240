# SIM240 学习笔记（接手项目版）

> 目的：用最少的概念理解 SIM240 的研究问题、代码结构和改动边界。  
> 更新：2026-09-21。本文是学习索引，不替代每个 CASE 的协议、日志或验证报告。

## 1. 一句话理解项目

SIM240 用 OpenLB 的单相 LBM，在**固定的 EX240 纳米沟槽几何**中计算液体沿不同平面方向的输运能力；从中提取等效迁移率 `K` 和水力阻力 `R`，再将其接入一个准静态挤压排液模型。

主线是：

```text
真实 EX240 沟槽几何
        ↓
OpenLB：固定间隙、稳态、单相流动
        ↓
提取 K_parallel、K_perpendicular 和 R
        ↓
研究高度/结构参数对各向异性的影响
        ↓
G5A 准静态模型：预测下压时的压力、载荷和排液阻抗
```

当前不主动进入：动态压头、材料转换、两相润湿、困气或液滴填充。

## 2. 坐标：最容易混淆、必须先记住

| OpenLB 坐标 | 物理含义 | 项目名称 |
|---|---|---|
| `+y` | 沿沟槽流动 | `parallel`（平行方向） |
| `+x` | 横跨沟槽流动 | `perpendicular`（垂直/横槽方向） |
| `z` | 基底到压头的壁面法向 | 下压方向，不是本微观 RVE 的主流动方向 |

纳米压印的物理过程是：

```text
压头沿 z 向下移动
        ↓
液膜高度 h 减小
        ↓
产生平面内压力梯度 ∇p
        ↓
液体沿 x/y 向外排出
```

因此，不要把“`z` 向下压”误说成“液体沿 z 向穿过沟槽流动”。微观 OpenLB Case 测的是固定高度下的 x/y 平面输运；G5A 才把该输运参数用于下压问题。

## 3. 两个核心物理量

### 3.1 等效迁移率 K

固定间隙的深度积分通量满足：

\[
\boldsymbol q=-\frac{\mathbf K_{\mathrm{eff}}}{\mu}\nabla_{\parallel}p.
\]

- `q`：单位宽度的排液通量；
- `mu`：液体黏度；
- `K_eff`：沟槽结构下的等效迁移率张量；
- `∇_parallel p`：`x-y` 平面压力梯度。

`K` 越大，越容易排液。

### 3.2 水力阻力 R

在同一驱动定义下：

\[
R=\frac{\Delta P}{Q}, \qquad R\propto\frac{1}{K}.
\]

`R` 越大，表示为了排出同样的液量需要更大的压力或力。

各向异性常用：

\[
A=\frac{K_{\parallel}}{K_{\perp}}
=\frac{R_{\perp}}{R_{\parallel}}.
\]

当 `A > 1`，液体沿槽方向比横跨沟槽更容易流动。

## 4. 为什么沟槽会出现方向差异

这是一个需要由速度、压力和耗散场验证的机制假设，而不是自动成立的结论：

- 沿槽方向（`+y`）流动路径连续，流体可沿槽延伸方向通过；
- 横槽方向（`+x`）需要跨越凸台—沟槽造成的横向几何变化；
- 这种几何重构可能提高局部速度梯度和压力梯度，从而使 `R_perpendicular > R_parallel`。

严谨表述应当是：**在当前固定网格和统一数值参数下，结果显示方向性阻力差异；其具体场机制必须由保存的速度、压力和耗散数据支持。**

## 6. 一个 OpenLB Case 的阅读顺序

不要一上来读完整个 `.cpp`。每次只按下面顺序读：

```text
几何
  ↓
材料编号（哪儿是流体、哪儿是固体）
  ↓
边界条件（周期面、Bouzidi 固壁）
  ↓
lattice 设置（D3Q19、ForcedBGK、tau）
  ↓
collideAndStream 时间推进
  ↓
measure / CSV / VTI 输出
```

常见入口在 `src/*.cpp` 的 `main()`；常见逻辑函数名包括 `prepareGeometry()`、`prepareLattice()`、边界设置函数、时间循环和 `getResults()`。实际函数名必须以对应源文件为准。

### 6.1 CASE 文件夹里的每一部分

每个 CASE 都是一套独立实验记录，而不只是一个 C++ 文件：

| 文件/目录 | 它代表什么 | 修改原则 |
|---|---|---|
| `README.md` / `PROTOCOL.md` | 实验问题、参数、输出和 PASS 标准 | 正式运行后不随意改历史协议 |
| `src/` | OpenLB C++ 主程序：几何、边界、LBM、测量和输出 | 对新实验修改副本，不改已完成 CASE |
| `src/*.cpp` | 此实验的“数值实验装置” | 先理解，再最小修改 |
| `src/Makefile` | 编译规则 | 一般不改 |
| `scripts/` | 源码生成、批量运行、审计、后处理辅助 | 可为新流程增加，保留旧脚本 |
| `config/` | Python 模型的输入参数，如 G5A 的尺寸和速度 | 复制为新配置，不覆盖已用配置 |
| `build/` | 编译产物与中间文件 | 不手改 |
| `results/` | 每个 run 的日志、CSV、场数据和图 | 永不手改原始结果 |
| `tests/` | 小型公式/输入/守恒测试 | 改模型时要保持通过 |

不同 CASE 即使代码相似，也是在回答不同科学问题。比如 `CASE/02` 问“沟槽是否有方向阻力差”，而 `CASE/04` 问“高度如何改变该方向差”。新实验必须新建独立 CASE 或独立 run/config，不能覆盖旧 CASE。

## 7. 结果是否可信：六项检查

每次看到一组结果，先检查：

1. `exit_code.txt` 是否为 `0`；
2. 是否有收敛证据；
3. 质量误差是否在冻结门槛内；
4. Mach 数是否足够小；
5. Bouzidi links、fallback、unresolved links 的几何审计；
6. `NUMERICAL_GATE`、`geometry_PASS`、`RESULT_PASS` 是否分别成立。

特别注意：程序退出、达到稳态、生成图片，都**不等于**整个 CASE 已通过。

## 8. 当前结果的正确证据边界

项目中存在不同日期的状态文件和较新的候选结果目录。处理时遵循：

- 旧的项目状态文件用于理解正式 Gate 定义；
- 每个最新 run 的日志、独立退出码、原始 CSV 和审计文件用于判断该 run；
- 单一固定网格的 `K`/`R` 可以报告为当前条件下的数值结果；
- 未完成独立网格收敛前，不称为“网格无关最终闭合参数”；
- G5A 通过解析/守恒门槛，说明该介尺度求解器可信；它不会自动补足上游微观 `K` 的网格无关性。

## 9. G5A 的位置

路径：`CASE/05_mesoscale/G5A_squeeze_resistance/`

它是 Python 的准静态模型，而非新的 OpenLB 动态计算：

## 第一课：材料编号——程序怎样知道哪里能流

学习文件：`CASE/00_validation/Case01_Poiseuille/src/case01_poiseuille.cpp`

这个 CASE 是一个没有沟槽的平滑薄通道。它的物理几何是：

```text
z ↑
  上固壁：material 3
  ─────────────────
       流体：material 1
       高度 h = 75 nm
  ─────────────────
  下固壁：material 2
z = 0
```

该文件中的 `materialAt(position)` 函数规定：

```cpp
position[2] < 0       → material 2 （下固壁）
0 ≤ position[2] < h   → material 1 （流体）
position[2] ≥ h       → material 3 （上固壁）
```

这里的 `position[2]` 就是格点的 `z` 坐标。材料编号不是物理材料参数，而是程序用来分区的标签：`1` 表示需要求解流动的区域；`2/3` 表示不能穿透的固体边界。

随后程序把不同物理规则安装在不同材料上：

```cpp
dynamics::set<ForcedBGKdynamics>(lattice, geometry, 1);
boundary::set<boundary::BounceBack>(lattice, geometry, 2);
boundary::set<boundary::BounceBack>(lattice, geometry, 3);
```

意思是：

- 对 `material 1`：使用受力 BGK 碰撞模型，允许液体响应 `+y` 方向体力而流动；
- 对 `material 2` 和 `material 3`：使用反弹边界，液体不能穿过上下墙面；
- `x/y` 方向由 `cuboids.setPeriodicity({true, true, false})` 设为周期边界：从一侧出去，会从另一侧回来。

**检查问题：** 若把一部分本应是固体的格点误标成 `material 1`，该位置会被当作流体，产生“漏流”；若把流体误标成 `2/3`，通道就会被错误堵住。因此，几何与材料审计是所有后续 `Q`、`R`、`K` 结论的前提。

### 第一课补充：初始化、审计与 PASS

`case01_geometry_check.cpp` 在指定 `material` 后会建立 `lattice`：

```cpp
UnitConverter<T, DESCRIPTOR> converter(dx, dt, width, 1.0, nuPhys, rhoPhys);
SuperLattice<T, DESCRIPTOR> lattice(converter, cuboids, loadBalancer);
```

- `geometry` 是地图：每个格点属于流体还是固体；
- `lattice` 是求解器：它在流体格点保存密度、速度、分布函数和外力；
- `UnitConverter` 负责物理单位与 lattice 单位转换；本配置中 \(\tau=1.7\)，\(\omega=1/\tau\)。

初始流体状态是 lattice 密度 \(\rho_{LB}=1\) 与静止速度 \(\mathbf u=(0,0,0)\)。这不等于物理水密度变成 \(1\ \mathrm{kg/m^3}\)；物理密度仍由 `rhoPhys=1000` 定义。

物理加速度在 `+y` 方向被换算为 lattice 外力：

\[
a_{LB}=a_{phys}\frac{\Delta t^2}{\Delta x}=2\times10^{-9},
\qquad \mathbf F_{LB}=(0,2\times10^{-9},0).
\]

此文件**没有** `lattice.collideAndStream()`，因此不模拟流动。它的 PASS 仅表示：流体节点数/体积、上下固壁、\(\tau\) 和体力换算都正确；不表示 Poiseuille 流动已经验证。

## 第二课：从初始化到真实稳态流动

学习文件：`CASE/00_validation/Case01_Poiseuille/src/case01_poiseuille.cpp`

与几何检查程序相比，这个文件增加了下面的完整计算链：

```text
初始化 lattice
  ↓
反复调用 collideAndStream()
  ↓
测量速度、通量、质量和 Mach 数
  ↓
用时间窗口判断稳态
  ↓
由通量计算 R 与 K
  ↓
与解析 Poiseuille 解比较并给出 PASS/FAIL
```

### 2.1 时间推进

```cpp
for (int step = 1; step <= maximumSteps; ++step) {
  lattice.collideAndStream();
  const Measurement state = measure(lattice, geometry, converter);
  converged = record(step, state);
  if (converged) break;
}
```

一次 `collideAndStream()` 包含两件事：

1. **碰撞**：格点内的分布函数向局部平衡松弛，并加入体力影响；
2. **传播**：各离散方向的分布函数移动到相邻格点。

重复这一步后，外力输入与壁面黏性阻碍逐渐平衡，速度场趋于稳态。

### 2.2 程序测量什么

`measure()` 只积分 `material 1` 的流体格点，输出：

- 平均速度 `meanVelocity`；
- 深度积分通量 `fluxJ`；
- 两个截面流量 `sectionQ1`、`sectionQ2`；
- 总流体质量、最大密度偏差、最大 lattice 速度；
- 有限值检查。

对本 Case，主通量是 \(J_y\)。它不是总流量 \(Q\)，而是用平面面积归一化后的输运量；代码用它避免几何面积定义混乱。

### 2.3 从通量得到 K 与 R

代码采用 \(G=\rho a\) 的体力驱动，对 `+y` 方向有：

\[
K_{yy}=\frac{\mu J_y}{\rho a},
\qquad
R_J=\frac{\rho a}{J_y}.
\]

光滑平板的解析值为：

\[
K_{yy,analytic}=\frac{h^3}{12},
\qquad
R_{J,analytic}=\frac{12\mu}{h^3}.
\]

这就是为什么这个简单 Case 是 EX240 结果的基础：若平板解析解都无法满足预设误差，沟槽的定量 \(K\) 与 \(R\) 也不能直接作为最终结论。

### 2.4 怎样判断稳态与可靠性

程序把最近 `convergenceWindow=1000` 个 \(J_y\) 值放入窗口，检查相对标准差和相对跨度；并同时要求：

- 质量误差小于 `massTolerance`；
- 密度偏差小于 `densityTolerance`；
- Mach 小于 `machTolerance=0.05`；
- 横向通量接近零；
- 两个截面流量一致；
- 所有数值有限。

稳态只是这些门槛的一部分。最终 `acceptancePass` 还要求速度剖面 \(L_2\) 误差和 \(J_y\) 相对解析误差均不超过 2%。

### 2.5 为什么可能退出码为 3

```cpp
return acceptancePass ? 0 : 3;
```

`0` 表示所有冻结门槛都满足；`3` 表示程序本身可能完整结束、甚至数值稳态和质量守恒都正常，但某项解析精度门槛未通过。必须据 `result.txt` 中的各项门槛判断，不能只看程序是否结束。
