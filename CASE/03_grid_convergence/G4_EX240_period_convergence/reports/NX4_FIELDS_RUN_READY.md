# 修复版 Nx=4 正式运行准备（2026-10-12）

运行入口：`scripts/run_fields_nx4.py`；独立程序目录：`build_fields_nx4/`。

## 放行依据与范围

固定引用修复版 `g4_period_nx2_fields_v1_20261012T001316+0800`，不按目录排序选择基线。
另存 `NX2_FIELDS_RELEASE_20261012.json`，绑定该批次与完整 scaling 的 164 个证据文件。
旧批次的原始文件、状态中的 pending 标记和中断批次均不改写。
单独的放行记录表达本轮人工证据审查已通过、允许准备和由用户启动 Nx=4，不代表 Nx=4 已通过。

## 执行安排

- 默认且固定一次一个稳态算例，每例 16 MPI ranks；六点依次执行。
- 六点 precheck 全部通过后才进入稳态；失败立即停，不启动剩余点。
- 新建时间戳批次 `g4_period_nx4_fields_v1_*`，拒绝覆盖，独立 latest 指针。
- 参数继承冻结协议：h=75 nm、dx=2.5 nm、tau=1、最大 960000 步，不延长。
- 启动前校验基线、短检查和程序哈希、现有 G4 进程、磁盘空间；锁防止重复启动同一新 runner。
- 每点保存日志、源码/程序/协议哈希、方向、驱动力、MPI ranks、独立退出码。
- 汇总保存 OpenLB 实际 commit、编译版本、库哈希、完整参数、仓库 commit/dirty 状态。
- 正式检查包含几何/q、数值门槛、收敛、独立退出、全程诊断行覆盖与有限值、19200 行切片完整覆盖、最终 CSV/VTK 输出存在。
- 线性响应与 E(2->4) 按冻结阈值检验；E 超 1% 时保留 E 表并标记失败。
- 全通过仍留 `HUMAN_RELEASE_REVIEW=pending`，需人工审查横槽质量轨迹；绝不自动进入 Nx=8。

`--check-only` 不启动仿真；本轮只运行这一准备检查和单元测试。
序列执行会减少资源争抢，但不保证墙钟时间比高并发短；未提供精确运行时长承诺。
关闭终端不影响 tmux；关机、重启、休眠会中断运行。无检查点续跑支持，不能把诊断 CSV 当重启文件。

解释边界：数值不变性、周期接缝完整性及大域质量审计；不是物理代表尺度或 RVE 收敛。
