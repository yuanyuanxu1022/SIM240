# 真实结果适配、收敛与资源审查：待审，不求解

2026-10-26。范围仅为第一篇矩形参考后端。源头是 `solve_entry_review_20261025` 的 9 个已组装混合问题、`solver_result_review_20261025` 的受门禁求解候选，以及 `raw_capture_review_20261025` 的记录基础部件。原 18 项执行位全为 `false`，参考协议仍是 `DRAFT_v2`。本轮没有调用 `KSP.solve`、没有形成正式 run_id，也没有改变任何数值门槛或预测状态。

## 1. 结果适配判断

旧写出器把一个二维速度节点误当成一个速度自由度；实际 DOLFINx `V` 块大小为 2，节点坐标数是展开后速度自由度数的一半。已对[写出器](../raw_capture_review_20261025/raw_writer.py)做最小修正：每个速度自由度写对应节点坐标及明确的 0/1 分量，并另写通过索引提取的速度原值，共 **16 组**原始数组。新增[适配器](bridge.py)从真实网格、MPC、速度/压力折叠映射及候选内存结果提取这些数组，核对原/MPC压力坐标顺序、P1权重、压力回填、速度/压力索引不重叠、周期映射来源。适配器不创建KSP或调用求解器。

[九项接口审计](evidence/bridge_audit.json)都使用真实矩形网格及真实DOF/MPC关系，但把**人工数值**填进向量；16份 `.npy` 对每项逐值和哈希读回。最细平板为104943混合自由度，其中速度展开93170、速度节点46585、压力11773、周期配对299。全部九项接口通过；旧纯合成[写出/日志测试](../raw_capture_review_20261025/evidence/synthetic_checks.json)也重跑通过。人工数组不满足流动方程，因此这些PASS只说明**接口顺序与文件读回**，不能说明真实求解结果、周期物理误差或论文公式正确。

人工场在现有16组原始数组方案下，最细一项实际文件合计6,731,472 B（约6.42 MiB），九个混合问题合计19,664,592 B（约18.76 MiB）。这仅量到数组文件，不含求解日志、失败快照、标量九项、诊断时序和独立验收文件；不能据此认定拟议4 GiB总盘额足够。

真实候选只返回内存向量与部分诊断；新适配器可以消费其成功返回值，但尚没有受审的真实进程调用链。`process_capture.py` 对正式子进程仍明确拒绝。残差历史、真实残差、周期迹、通量/散度、能量、单位恢复、源及求解器版本仍需另存并由独立程序重算；16组数组并未完成先前 `record_contract.json` 的全部字段。

## 2. 收敛风险与保留规则

当前候选为 GMRES + `PC NONE`，显式指定未预条件残差类型，成功后在周期回填**之前**以原矩阵和右端重算 `‖b−Ax‖₂/‖b‖₂`，并要求PETSc退出原因表示收敛且真实残差不超过显式目标。这一数值检查的**位置和定义**合理，但求解分支未执行，不能证明会达到 10⁻¹⁰ 或 10⁻¹²。PETSc指出，GMRES监控值可能是估计值，正式判断需保留退出原因及重新计算的真实残差；对有压力常数零空间的奇异系统，还需保持零空间和兼容右端的检查。[PETSc KSP手册](https://petsc.org/release/manual/ksp/)、[PETSc残差监控说明](https://petsc.org/release/manualpages/KSP/KSPMonitorResidual/)。

目前有三项具体缺口：

1. `DiagnosticGMRES.validate()`仅要求迭代上限和重启数为正，没有与资源预算绑定的上界；极大值会增加Krylov向量和 `max_iterations+1` 残差历史内存。必须在后续受审配置中显式限制，并记录实际参数，不在这里臆定数值。
2. 若退出原因≤0或真实残差超标，候选会抛出 `CandidateSolveFailure`，诊断内保留KSP历史和最后真实残差，**但未把已有的代数向量交给写出器**。异常或进程中断时也没有保证能保存部分原始场。这不满足失败保留合同，正式入口接线前要先补。
3. 现在没有求解阶段的逐项峰值RSS/磁盘、资源到限停止与失败退出的完整审计。`process_capture.py` 的 `ru_maxrss` 是该父进程所有子进程的累积高水位，不应当充作单个算例的峰值。

压力/速度周期迹、散度、剖面、解析K、能源平衡和网格/代数重复比较是**数值与物理验收的另一层**；代数残差与独立退出0无法替代。草案阈值仍未冻结，旧G4与历史网格FAIL不变。

## 3. 资源方案与下一道门

先前最细平板的组装预检实测RSS299272 KiB、1.14秒；矩阵104943维、3103649非零。按32位列索引估计的CSR三数组约35.9 MiB、重启50时51个双精度基向量约40.8 MiB，都不包含PETSc其它存储、临时向量和预条件器。2026-10-26审查时主机可用RAM约16.64 GiB、可用盘约337.03 GiB，这是瞬时快照。提议的每次可用RAM≥4 GiB、证据盘4 GiB、18项总2小时仍为**未验证的上限**，不能由组装耗时线性外推。未经预条件的GMRES对这种混合鞍点系统是否收敛，证据不足，无法判定；PETSc说明预条件器显著影响Krylov收敛，场分裂/Schur是可研究接口而非本项目已验证方案。[PETSc KSP手册](https://petsc.org/release/manual/ksp/)。

下一步只建议先**设计并审查**诊断试跑顺序与预算：从小网格制造解和粗平板逐项开始，再考察中/细网格；每项记录实际残差曲线、迭代数、独立退出、峰值内存、耗时和原始输出量；与待审预条件方案比较后才能决定是否保留 `PC NONE`。这只是未来许可审查的方案，当前不给启动命令。资源不足时应 `RESOURCE_HOLD`，不降残差/物理误差门槛。参考协议冻结、求解版本和明确运行授权是运行前的独立条件。
