# 待审可调用求解代码与结果记录方案：静态审查

2026-10-25。用户要求确认既有预检状态，继续审查可调用的求解代码和结果记录方案，**仍不执行求解**。本目录不改原 18 项白名单、原草案协议、G4 候选锁或历史结果。新文件是单独的**候选实现和记录合同**；没有实际速度、压力、通量、计算 run_id 或求解退出码。

## 当前确认到哪里

前一[9 项组装/压力预检的独立复核](../solve_entry_review_20261025/evidence/independent_review.json)仍为 PASS：9/9 混合矩形的矩阵/右端哈希一致，正确约化常压向量在右/转置零空间中，旧错误候选和不相容右端被拒绝。这是**预检状态**，不是已经完成的求解。原 `solve_entry_review_20261025/entry.py` 返回组装对象但没有 KSP 或 `solve()`；原 `src/records.py` 只有明确标注为 `TEMPLATE_NOT_A_RESULT` 的空模板，不能当原始结果写出器。

本轮新增 [`candidate_solver.py`](candidate_solver.py) 作为**可调用但未执行的候选函数**。它先要求调用方提供新版本的白名单执行授权、独立审核的 release，以及与当前矩阵/右端对应的哈希；**当前全部 18 项 `execution_authorized=false`，所以九个混合案例都在创建求解器之前拒绝**。唯一的 `ksp.solve()` 位于该门禁之后，无命令行启动入口。配置必须显式给出 GMRES 相对阈值、真实残差目标、最大迭代和重启长度；这里没有把待审草案的 10⁻¹⁰/10⁻¹² 门槛自动变成正式运行许可。

候选采用 **GMRES + 无预条件器**，只作为最小代数诊断路径。PETSc 文档建议对带已知零空间的奇异系统使用 GMRES；这并不说明无预条件器能在最细的 `104943×104943` 混合矩阵上达到时间/内存预算。若未来真正调用，代码会保存 PETSc 原报告的残差历史、退出原因和迭代数，并在**周期从属位置回填前**用原始 `A`、`b` 独立重算 `‖b−Ax‖₂/‖b‖₂`；未收敛或未达显式真实残差目标时抛出失败，不伪称 PASS。之后才回填周期压力，并以 P1 三角形面积权重去均值。该运行分支**没有被执行过**，因此还不能称求解器数值验证通过。

## 结果记录方案

[`record_contract.json`](record_contract.json) 是 `DRAFT_NOT_APPROVED_NOT_A_RESULT`：求解前列出 10 组输入/几何/版本/矩阵绑定与资源字段，求解后列出 16 组独立退出、完整日志、原始双精度网格和场、压力原值与面积去均值、真实残差、通量、散度、能量、周期迹及文件哈希，失败时保留 6 组阶段/原因/部分原始证据。物理平板的 `J、K、R` 和非均匀制造源的泛函分开；MMS 的 `Ĵ=1/6` 不转写成物理迁移率。模板的 run_id、退出码、原始场和真实残差全为 `null`，数值 Gate 保持 `NOT_EVALUATED`。

本轮**没有实现**独立进程启动器、完整日志/退出码捕获、原始网格/场写出器、通量/能量/周期迹提取、结果独立验收器或 9 项标量求解路径。因此候选函数返回内存中的数组也不能构成老师可复核的正式结果。未来运行前还须评估预条件器与资源、冻结求解参数、补全这些记录和验收环节，且需要新的授权和逐项 release；当前不给运行命令。
