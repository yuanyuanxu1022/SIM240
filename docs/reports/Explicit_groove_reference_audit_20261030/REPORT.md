## 2. 来源问题核实到什么程度

### D2：二进制与数据分组完全重合

52份清单均保存binary_sha256，均未直接保存source_sha256、generated_source_sha256、openlb_commit、compiler、compile_flags。当前指定路径的程序哈希与28条记录相符；另外24条记录重复指向已被替换的D2程序路径。这里的“24”是记录数，不是24个不同文件损坏。

2026-10-28的旧恢复报告用时间戳、当前依赖文件等补充了线索，但把“28条当前程序相符”写成完整构建绑定过强。mtime、当前Makefile或当前源码存在，不能单独证明历史编译使用了哪些源码/依赖；旧报告关于D2没有Makefile的说法也与当前文件存在状态不同。本轮只据当前可核证据给出限定，不回写旧报告，不声称已穷尽所有磁盘或远端档案。

### D4：可复用的主要工程基础

38条原始结果与既有独立标量验收值一致；所选直接源码/程序/配置/物性/库绑定以及既有验收所选标量原文件哈希全部满足。原生`RESULT_PASS=false`仍是执行时记录，已有外部验收证书另存，本轮不将其误判为38条失败。

比较接口还必须保留驱动差异：这些常规显式输运记录a=1e5m/s²、rho=1000kg/m³，等效G=rho*a=1e8Pa/m；GDI01/C01则为1e6Pa/m。应先以K=mu*J/G（等价nu*J/a）比较导度，不能直接拿不同G下的J或Q比大小。J是流体体积积分除平面面积，H是流体平均厚度；源码体力速度包含半步修正。周期压力字段是扰动，p_max−p_min不能替代宏观驱动压降。

## 5. 最小补证与补算缺口

详细清单见[MINIMUM_GAPS.md](MINIMUM_GAPS.md)，逐方向—网格候选输入见[proposed_minimum_matrix.csv](proposed_minimum_matrix.csv)。优先次序如下：

1. **先做零求解的来源收口**：恢复/重建方案C及h75链的独立验收入口；区分历史输出与当前库环境；复用D4基础回归和源/库绑定。不能恢复的历史源码字段继续标缺失，不造档。
2. **建立一个可追溯基准**：保留已完成的D4 h75/d100/w120两方向5nm结果。能否复用旧2.5/1.25nm由同物理/源码差异及C链资格审核决定；若不能形成可信同族链，最小新补为两个方向×2.5/1.25nm=4项，采用新版本输出，原FAIL保持。
3. **取得真正的新参考**：两个候选×两个方向×三档网格=12项参考求解的规划矩阵；先完成运行前来源/几何/资源与分析协议审核，再分阶段运行。三档是可检查空间收敛的起步设计，不保证一定足够；没有渐近趋势或参考不确定性过大时，不应宣布资格完成。
4. **单列必要控制与可选桥接**：h30与新深度可能需要平板/驱动力/统计窗控制；最小数量依资格协议决定。若要解释旧“标定/扩展”跨构建混杂，可复用新h75/d100回归，再补h75/d75两方向同源桥接2项；它们是已见条件且不证明所有历史程序等价。若只做固定V2的前瞻性检验，桥接不是必然前置。

由此，主参考矩阵为12项新条件，加0–4项基准加密缺口；**12–16不是承诺完成闭环的全部计算数**，不含必要控制、额外精度检查或瞬时挤压直接参考。没有任何新项在本轮启动。

参考误差应小到足以分辨原公式与V2的差别。预先指定允许的数值误差预算、最小有意义改善及“证据不足”的处理，不从看到改善幅度后反推可接受阈值。报告有符号/绝对误差与不确定性；若差别无法分辨，结论为无法判定。只改善部分条件或某些条件失效也应完整报告。
