## 2. 遇到并修掉的一个坑（值得记住）

第一次链接失败：

```
undefined reference to std::__cxx11::basic_string<...>::_M_replace_cold
```

**原因**：OpenLB 的源码目录里残留了本机编译的 5 个 `.o` 文件（2026-09-02，用 **GCC 13.3** 编译），被 rsync 一起传了过去。服务器是 **GCC 11.4**，`make` 看到 `.o` 比 `.cpp` 新就跳过编译，直接拿去链接，于是撞上 GCC 12+ 才有的符号。

**修法**：删掉服务器上的 `src/**/*.o`、`src/**/*.d` 和 `build/lib/libolbcore.a`，重新 `make core`。

**教训**：跨机器传源码时**必须排除 `*.o`、`*.d`、`*.a`**，否则会带着上一台机器的编译产物去做"假编译"。这类错误看起来像代码问题，实际是传输问题。

## 3. 服务器上的编译细节

工具链：
- `mpic++` / `g++` 均为 **GCC 11.4.0**（Ubuntu 22.04.3）
- OpenLB 的 `config.mk` 采用 `CXX=mpic++`、`PARALLEL_MODE=MPI`、`PLATFORMS=CPU_SISD`、`FLOATING_POINT_TYPE=double`、`USE_EMBEDDED_DEPENDENCIES=ON`（自带 zlib/tinyxml2，不依赖系统包）

先 `make dependencies`（编出 `libz.a`、`libtinyxml2.a`、gtest），再 `make core`（编出 `libolbcore.a`，只有 5 个目标文件——OpenLB 绝大多数是头文件实现，这是正常形态，本机也是 5 个）。

算例编译命令（服务器实际执行，注意 `OLB_ROOT` 指向服务器路径）：

```
mpic++ -O3 -Wall -Wextra -march=native -mtune=native -std=c++20 \
  -DOLB_VERSION=\"882924a9cfc8\" -pthread -DPARALLEL_MODE_MPI \
  -DURV_PREPARATION_ONLY=0 -DPLATFORM_CPU_SISD -DDEFAULT_FLOATING_POINT_TYPE=double \
  -I/home/yuanyuan/openlb/src -I/home/yuanyuan/openlb/external/zlib \
  -I/home/yuanyuan/openlb/external/tinyxml2 -MMD -MP \
  -c urv_reference.cpp -o ../build/urv_reference.o
mpic++ ../build/urv_reference.o -o ../build/urv_reference \
  -L/home/yuanyuan/openlb/build/lib -lolbcore \
  -L/home/yuanyuan/openlb/external/lib -lz -ltinyxml2 -lpthread
```

版本字符串 `882924a9cfc8` 与本机**一致**——`Makefile` 用 `git rev-parse --short=12 HEAD` 生成，与机器无关。
