# TGE-MRR-v0.1：失败后资源修订最小范围草案

状态：仅审查建议，未采用、未实现、未封存、无执行许可。用户本轮只授权只读核查；本文件不批准重试、提高限制或新运行。

## 建议准备范围

1. 新隔离候选复用当前已封存同一S1 ELF及构建来源；只改资源包装、独立监督/回执、cwd/输出计费、身份与新封存接入。旧CASE、合同、attempt、日志、结果保持。若换服务器/CPU或重编，另定构建可比性范围，不视为本地提限的等价替换。
2. 单进程AS须高于已核9.32424GiB部分载荷并有可解释余量；这个条件必要而不充分。16GiB AS/18GiB整组/22GiB可用RAM/4GiB宿主余量为待测候选，不是新批准值或成功保证，不能只改一个常量。是否采用禁组内swap与整组硬限，须核实宿主机制/权限/后代归属/监控退出；机制未知就HOLD，不降格冒充已受控。
3. 新零步保持describe→precheck→initialize→一次初态读回，每次各一次、0时间推进、失败即停。原生与读取串行并回收前进程。300s原值不由10.42s内存失败自动增加；是否调整须独立说明和采用。PERF/正式时限不在此次最小接入内。
4. 必需观测：资源方案/SHA、命令与cwd、子进程PID及开始/结束、实际生效AS、独立退出、精确停止原因、峰值RSS（wait4等）、VmSize/VmPeak/VmRSS/VmHWM采样及间隔/漏峰局限；独立组的memory.peak/events/oom与swap、宿主可用RAM最低观测值。无法记录就如实标缺，禁止把部分采样写成精确峰值。监督器不能与被限组一起失去全部终止证据。
5. 封闭本身份全部输出：日志/回执、原生/VTK、读回分析、tmp/失败残留，排除旧只读基准重复计费；临时cwd改变须用软件检查验证配置绝对路径与来源哈希仍一致。输出周期观察值只称停止阈值，硬配额须真正核实。计数/字节/磁盘前置、轮询间隔和清理时限需同一清单，不借旧4GiB或未采用16/64GiB假装已闭合。
6. 软件检查只用mock或小型非求解器进程验证限制、整树终止、超时、OOM回执、输出逃逸拒绝、新/旧合同相互拒绝及失败停止；不得启动urv_reference或pvpython。授权准备后才做；本轮未实施。
7. 新准备权限全部关闭。采用与软件检查通过后，另行获取明确覆盖失败后新3＋1和具体资源的授权，复核封存/届时资源，生成新合同及用户手动命令。无自动重试或连续限额搜索；新3＋1通过后另审有限PERF，再据实另定正式计算。
