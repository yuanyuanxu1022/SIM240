## 1. 需要收回的三处表述

### 1.1 "光加迭代步数走不通"说过满了

改为：**仅增加迭代预算已经显著改善平板导度**（−8.943434% → +0.013878%），这条证据成立且是本次最有价值的一条；它**不能**解决的是零分量归一化残差造成的停止与接收问题。前者是求解量不足，后者是判据与解的精度脱钩，两件事不能合并成一句话。

### 1.2 平板 Uz 近零不能推广到沟槽；且"源项恒为零"本身说错了

沟槽台阶附近流体上下绕流，Uz 是必须求解的物理分量。更重要的是我原话"Uz 方程源项恒为零"是错的：T 分支求解 `-ν∇²U = a·e_x` 再减 `∇p`，z 分量是

```
-ν∇²U_z = -∂p/∂z
```

源项是压力梯度，不是零；竖向体力为零不等于该方程源项为零。平板之所以出现 Uz≡0，是因为**该解**满足 ∂p/∂z=0，这是解的性质，不是方程的性质。把解的性质当成方程的普适结论，正是把平板例外无条件搬到沟槽的根源。

### 1.3 "假偏差 / 与论文结论同向"指代错误

收回。8.94% 是**未收敛近似的真实数值偏差**，不能称假误差。正确表述：**未收敛参考会制造两个求解器之间的虚假差异**，不据此支持任一方高估 K。PROTOCOL §5 与平板报告 §4 的相应句子一并改写。

同处删除"U 残差 1e-9 对应 K 误差约 1e-4%"：两条平板轨迹点不足以建立跨几何/网格/初场的残差—K 误差界，且第二个点还含空间离散误差。该数字降级为平板诊断观察，不作沟槽误差保证。

### 2.1 B1：沟槽恢复冻结的原生完整控制，平板例外单独限定

**沟槽（d>0）**：`residualControl` 回到冻结值 —— p 1e-10、U 1e-10（tight 各 1e-11）；P 的 v 1e-10（tight 1e-11）。接收要求**末次迭代上全部字段同时达标**，逐项检查、向量按 `cmptMax` 取最大分量；**不使用任何单分量 fallback**，也不存在"字符串出现即通过"的独立分支。

**平板（d=0）**：例外只在此处启用，且写死在 `case.json`（`flat_zero_component_exception: true`），沟槽不可继承。四个条件同时满足才接收：

1. 退出码 0，且日志剥尾空白后以 `End` 结束；
2. 末次迭代 p 与 Ux 均达原生阈值；
3. 导出场给出 `max|Uz| ≤ 1e-9 · max|Ux|`，即机器零的定量证据，而非"不检查"；
4. 既有解析检查仍须同时满足：K 相对 h³/12 ≤0.1%、剖面 L2 ≤0.1%。

给平板的理由只有一条：**d=0 有精确解作锚**，接收最终由解析误差把关，残差只需证明"已停止演化"；沟槽没有这个锚，因此不设此例外。这解释了为什么例外不能推广，而不是因为"平板零分量，沟槽大概也零"。第 3 条把"排除 Uz"从**删除检查**改成**定量证明其为零**，与当前 fallback 有实质区别。
