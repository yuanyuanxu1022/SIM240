## 3. 两个需要先处理的接口缺口

### 阻力定义

OpenFOAM Foundation 13 官方 DarcyForchheimer 定义体积源项 `S=-(μ d + ρ|U|f/2)U`，d 的单位为 m⁻²。当前本项目深度积分导度 K 单位为 m³，二者不能原数值互填。官方依据：

- https://cpp.openfoam.org/v13/DarcyForchheimer_8H_source.html ，描述段。
- https://cpp.openfoam.org/v13/classFoam_1_1fv_1_1porosityForce.html 。

定义核对候选为 `q=-(K/μ)∇p`，q 单位 m²/s；如果明确采用等效厚度 H、`Ubar=q/H`，并由纯 Darcy 项承担全部平均阻力，则有 `κ=K/H`、`d=κ⁻¹`（主轴上 `d_i=H/K_i`）。**这仅是有条件的单位与平均定义接口，不是本轮冻结的通用接入公式。** H 应用凸台下间隙、平均液体厚度还是包络厚度须由模型定义裁定；若另解析上下壁黏性耗散，不能再默认全阻力 d 直接叠加。原配置的 y 分量 d_y=0 只表示该方向没有此项附加 Darcy 阻力，不表示沿槽方向总阻力为零。

当前 PATH 可找到 `/home/dell/OpenFOAM/OpenFOAM-13/` 的 foamRun、blockMesh、checkMesh、wmake，`etc/bashrc:36` 声明版本 13。仅证明本机存在这些入口，未运行工具或验证构建兼容。参考文件头同时出现 Foundation 13 与 OpenCFD v2412，文件头不能独自决定实际版本。本机 porosityForce 示例还给出嵌套 `DarcyForchheimerCoeffs` 写法，与参考字典布局有差异；本轮不运行字典解析，兼容性保持未验证。后续应以选定目标版本的实际解析与基准为准，不沿用上一轮 OpenCFD 文档就承诺兼容。

### 挤压运动与守恒

完整目录树中，该候选未见 `constant/dynamicMeshDict` 或其他明确的 mesh mover 配置；在已下载入口中 `zoneMotionCoeffs` 只见于 topoSetDict。对本机标准 OpenFOAM-13 的 src/applications 定点搜索未找到该关键词消费者。故本轮**未找到这组位移参数被读取并驱动网格/等效体积源的完整证据链**。可能另有未提供的修改或运行环境；不能据此证明绝对没有，也不能报告已实现正确挤压。

全充液挤压需要体积变化与排液方程一致。仅填 `movingWallVelocity` 和一个位移数字，不足以证明液体受到所需闭合驱动；固定时刻参考解也必须施加与闭合相符的壁面法向速度及开放边界。新 OpenFOAM 算例须明确选定网格运动或经过审核的深度平均源项实现，并核对相同的体积收支。

## 6. 比较指标与证据分层

1. **主指标**：`R_sq=F_net/V`，单位 N·s/m。F_net 需共同规定环境压力扣除、作用面/投影面积和应力口径。二维模型压力积分与三维总法向应力不能未检查就视为同一量。
2. **次指标**：同一区域两槽向的 `χ_sq=R_sq,along_short/R_sq,along_long`，无量纲。区域长宽及其他条件固定，仅旋转槽向。
3. **压力诊断**：同一过压基准下的场、预定中心线剖面、中心压力或峰值；跨模型须先规定厚度平均/投影与采样位置。报告带符号量，不以绝对值隐藏符号。
4. **守恒诊断**：在刚性不可压缩全充液假设下，`Q_out,total=V A_projected`；同时记录各边流量分配与体积收支残差。恒速时总排液量受守恒约束，不宜单独用来证明修正精度改善。
5. **实现一致性**：使用相同 K 时比较两端输出，记录网格/求解误差、边界及降阶差异。若不一致，先定位单位、平均方式、运动源项、重复壁面阻力；不调整 V2 来补偿程序错误。
6. **应用预测偏差**：另有合格、同条件、显式解析沟槽的参考后，比较 `e_R=(R_model-R_ref)/R_ref` 与其绝对值、修正前后变化。独立参考不得使用原/V2 等效系数，不因用了另一软件就自动合格。压力/应力、网格、有限边缘与尺度分离均须审核；还需未参与拟合的新条件，修正不改善时保留该结果。

本轮不规定或降低任何通过阈值。二维/OpenFOAM 各算原系数与 V2 是两套实现、两组输入；二者相近只支持一致性，不能单独支持准确性或真实填充工艺结论。
