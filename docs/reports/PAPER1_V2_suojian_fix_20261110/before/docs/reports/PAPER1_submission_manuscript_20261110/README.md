## 1 为什么要有这个目录

母本是**内部工作稿**，参考文献后面还挂着 4 个内部附录：

| 附录 | 内容 | 问题 |
|---|---|---|
| A 图件来源与编号映射 | 新图号 / 文件名 / 旧图号 / 状态 | 暴露本地文件路径；**且把图 1—4 的图注整段重抄一遍**，整份转 PDF 会出双份图注 |
| B 正文数字的可追溯性 | S1—S14 与表号对照 | 内部追溯表，审稿人不需要 |
| C 投稿前需补齐 | 作者/基金/利益冲突/CRediT/AI 声明清单 | 给作者看的待办清单，不能出现在投稿件里 |
| D 版本与修订记录 | 内部版本日志 | 同上 |

这些内容留在母本里是对的（作者要查），但**不能随稿投出**。本目录就是"把附录 A—D 摘掉之后的那一份"。

## 3 一处与原计划的偏离：附录字母仍是 E，没改成 A

终审清单里写的是"附录 E 重编为附录 A"。实际做的时候发现这样做会引入新矛盾，所以**保留 E**，原因三条：

1. **式编号跟着走**。附录里是式 (E1)—(E8)，正文有 8 处回引"式（E1）…（E8）"。改字母就得同时改 8 个 `\tag` + 8 处回引，中英各一遍，共 32 处，纯属增加出错面。
2. **补充材料引用了它**。中文补充 L250、英文补充 L250 各有一句"沿用附录E / Appendix E 的假设"。只改正文不改补充，审稿人会看到正文叫 A、补充叫 E。
3. **改补充要连带 25 个内部链接**。补充材料里有 25 处指向 `docs/reports` 下其它审计目录的相对链接，不能单独拷一份出来改（拷出来就全断链），必须连数据一起打包，那是独立的打包步骤。

**结论**：现在正文与补充材料一致、链接全通、式编号自洽，这是当前状态下的最优解。
真要改字母，等补充材料打包时**四份一起改**（中文正文标题 1 处、英文正文标题 1 处、中文补充 L250 的"附录E" 1 处、英文补充 L250 的"Appendix E" 1 处），一次到位。

> 顺带说明：投稿排版时期刊的 copy editor 一般会统一重编附录字母，到时按他们要求改即可。

## 4 怎么重新生成 / 怎么自查

母本改过以后（比如又合入新证据），在本目录执行：

```bash
python3 build_submission.py
```

脚本会重新生成两份投稿稿。它做了三件事防错：

1. **每处替换都断言"目标串恰好出现 N 次"**。母本结构一变（比如标题改了、段落被拆），脚本立刻报错停下并打印是哪一处，不会静默漏改，也不会改错位置。
2. 生成后校验**禁词**：`docs/reports`、`PAPER1_`、`Astra`、`Codex`、`author-review`、`导师审阅`、`本稿未含`、`附录 B/C/D`、`Appendix B/C/D`。命中即失败。
3. 校验**相对链接**能否解析到真实文件（图片、补充材料锚点）。断链即失败。

只想确认"现在磁盘上的投稿稿是否仍与母本一致"，不动文件：

```bash
python3 build_submission.py --check
```

人工复核最直接的办法是逐行比对，预期只会看到第 2 节列的那几类改动：

```bash
cd docs/reports
diff SIM240_中文稿_导师审阅版_20261022.md PAPER1_submission_manuscript_20261110/SIM240_submission_CN.md
diff SIM240_First_Paper_English_20261028.md PAPER1_submission_manuscript_20261110/SIM240_submission_EN.md
```

## 6 投稿前仍需作者做的事（本目录**没有**替你做）

| 项 | 为什么不能代做 |
|---|---|
| 作者、单位、通讯信息 | 只能作者提供 |
| 基金资助、致谢 | 同上 |
| 利益冲突声明 | 需全体作者确认，不能代写"无冲突" |
| 作者贡献（CRediT） | 需作者确认分工 |
| AI 使用声明 | 需按实际用途如实写 |
| 数据可用性最终措辞 | 现在是"私有仓库 + 受限访问"。多数期刊要求至少审稿期内可获取，需作者定：公开？给审稿人临时权限？还是存到机构库并申请 embargo |
| 补充材料打包 | 补充材料有 25 处指向内部审计目录的相对链接，必须连数据一起打包或改成"见补充数据文件 X"，见第 3 节第 3 条 |
| 目标期刊格式 | EJMB 的模板、参考文献样式、图表规格尚未套用 |
| 图表转为期刊要求的分辨率与格式 | 现在是 md 内嵌 png 链接，正式投稿要单独的图件文件 |
