## 4. 我这轮新查到的一条（Pro 和学生都没写）

**7.93 pp 不是构建差异造成的——这一点这批数据本身就能证明，但没写出来。**

查二进制身份：

| 点位 | 二进制 SHA | Kyy 的 K_LB |
|---|---|---:|
| h75/d100 主地图 | `285f67a0`（标定组） | 9.8340759586e-23 |
| h75/d100 构建复跑 B | `57611b21`（扩展组） | 9.8340759586e-23 |
| h100/d100（新点） | `57611b21`（扩展组） | 1.6547640831e-22 |

**两个推论，都必须写进论文：**

1. **跨程序对照其实已经做了。** 论文正文 `:434` 明说"由于缺少同条件跨这两组程序的对照，现有记录不能分离潜在构建差异"。**但 h75/d100 的构建复跑正好就是同条件跨两组二进制的对照，K 差异 0.0%（到 16 位有效数字）。** 这半句可以改了——至少对这个几何，两组程序身份等价。

2. **7.93 pp 的漂移与二进制身份无关。** 把 h75 与 h100 都取在 `57611b21` 上：+5.897% → −2.028%，差 7.925 pp。同一二进制内部的漂移，排除了构建混淆。这是学生自己做出的控制，只是没意识到它的证明力。

> 注意边界：这条只覆盖 h75/d100 一个几何，不能推广成"全图两组程序等价"。学生原文"该对照仅覆盖一组几何，不证明全图构建等价"这句是对的，保留。

## 6. 明确不建议做的事

| 不建议 | 理由 |
|---|---|
| 现在把 C4（含 h 项）升格为 V3 | C4 是回顾性拟合、无第一性推导、无盲测、无新宽验证。升格 = 重新参数化 + 重开盲测，而盲测在当前条件下不可认证（三证 false），会直接拖停投稿线。**写成"未来工作"即可。** |
| 因 7.93 pp 去补一批标定点"救" V2 | 方向错误。问题不是标定点不够，是函数形式少一个变量。补点只会让单变量拟合更紧，漂移仍在。 |

| 把两套文件清单合并 | 口径不同（8,836 vs 1,475），合并后两边都失去独立可核性。 |
