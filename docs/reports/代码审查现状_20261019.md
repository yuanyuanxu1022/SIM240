## 二、发现的两处问题（不影响本论文结果，但应记录）

### P1（轻）：横向通量的收敛门限在量纲上偏松

第 768/786 行判据：

```
windowCross <= crossFluxTolerance   // crossFluxTolerance = 1.0e-12 m²/s（绝对值）
```

但主通量量级本身就是 **~1e-12 m²/s**（如 h50/d25/P：J_main = 1.939e-12）。
因此该门限等价于「允许横向通量达到主通量的 ~50%」——作为对称性检验**偏松**。

**实际数据远好于此**：同算例 `window_cross_abs_max = 1.579e-21`，相对主通量约 **8e-10**，即对称性保持到 9 个量级。
所以**不影响任何已报告结果**；但论文正文把「横向通量 ≤1e-12 m²/s」当作验证条件陈述时，审稿人可能质疑该阈值缺少相对标度。

**建议**：正文可补一句「实测横向通量相对主通量 <1e-9」，比单给绝对阈值更有说服力。**不需要新计算**——diagnostics.csv 里已有该列。

### P2（轻）：D2 的斜向驱动分支与自身收敛判据不自洽

`parseParameters` 允许传入角度（第 174-200 行），但收敛判据对所有模式统一要求 `crossFlux <= 1e-12`（绝对值）。
斜向驱动必然存在真实横向通量，**该分支将永远无法满足判据**，只会跑满 60000 步后报 converged=false。

**但**：6 个斜向算例实际由**另一个程序** `D3_oblique_groove_tensor_check` 计算（其判据为横向相对标准差 ≤1e-6，与源码第 786 行一致），D2 的结果目录中也确实没有角度工况。
→ **属潜在缺陷，未污染本论文任何数据**。
