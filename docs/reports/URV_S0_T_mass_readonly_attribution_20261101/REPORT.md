# 横槽旧质量轨迹差异：专项只读归因与裁定

2026-11-01。**已查明一项确定的编译后差别：旧程序质量累计的最后一次乘加采用FMA，新程序先舍入乘积再相加。该差别确实能改变同一输入下的旧质量累计尾数。** 新增补偿统计后，“旧质量累计源码表达式保持”没有同时保持其机器运算路径，这是实现层面需要纠正的证据表述。

**当前明确裁定仍为S0 HOLD：P通过、T不接受。** 现有保存材料没有190个差异时点的完整、按遍历顺序排列的双精度密度输入，因此尚不能逐点证明历史上全部190个差异都仅由这一机制产生，也不能依据末位很小直接解除冻结回归条件。

本轮仅读取已有源码、历史/当前构建记录、原始结果及实际运行过的ELF，使用nm/readelf/objdump作静态检查，并在新报告目录作算术核对。没有调用旧/新求解器、编译器、调试运行、时间推进、拟合或独立验收入口；没有修改原程序/原回执/原门槛或启动S1。AI参与的证据审查非独立人工科学终审。

## 2. 源码相同，最后一步舍入路径不同

两份源码的旧质量语句均为：

```cpp
value.mass += rho * rhoPhys * dx * dx * dx;
```

新URV还把同一单元质量项传给Neumaier补偿累计。两份ELF中的rhoPhys常量读出均为1000，dx及实际配置相同。Measurement布局中mass偏移均为16字节，volume偏移为8字节；打包指令的高64位对应mass，不能把其他FMA误认成质量累计。

令RN表示舍入到双精度，p=RN(RN(RN(rho×1000)×dx)×dx)。从实际指令导出的两种旧质量更新为：

- 旧：M_next=RN(p×dx+M)，最后乘加只舍入一次。
- 新：term=RN(p×dx)，M_next=RN(term+M)，最后乘法和加法各舍入一次。

这是编译表达式融合的具体区别。Intel指令语义说明融合乘加采用一次最终舍入；GCC13.3文档说明表达式融合可生成这种操作，Python fma文档用于下述算术核对。[Intel指令手册](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-2c-manual.pdf)、[GCC13.3优化选项](https://gcc.gnu.org/onlinedocs/gcc-13.3.0/gcc/Optimize-Options.html)、[Python fma](https://docs.python.org/3.14/library/math.html#math.fma)。这些文档解释指令语义，不替代项目ELF证据。

| 路径 | 旧程序的关键指令 | 新程序的关键指令 |
|---|---|---|
| 横槽T | 0x3f661 vfmadd213pd，写volume/mass打包项 | 0x3fee8 vmulpd后0x3fef1 vaddpd，写同一打包项 |
| 沿槽P | 0x3fb16 vfmadd213pd | 0x404b8 vmulpd后0x404c1 vaddpd |

新T的0x3feed把已舍入打包乘积的高位单元质量提取出来，0x3fef8继续用于补偿累计。新P也有同样的数据复用。可直接观察到：为了供新统计使用，单元质量乘积被独立算出并舍入，旧累计共享这个乘积，因而失去了原来的最后一步融合。证明的是现有二进制的数据流；没有编译器优化转储，不声称已查到具体内部优化pass。

证据：[old_T_mass_path.txt](old_T_mass_path.txt)、[new_T_mass_path.txt](new_T_mass_path.txt)、[old_P_mass_path.txt](old_P_mass_path.txt)、[new_P_mass_path.txt](new_P_mass_path.txt)，完整函数反汇编及机器字段核对见[verified_machine_paths.json](verified_machine_paths.json)。横槽驱动drive=0走第一分支，沿槽drive=1走第二分支，已用函数入口条件与源码对应。

同一打包指令还处理volume；本h75新/旧结果中的实测体积相同。不能把“本案只有mass两列观察到差异”扩大为只有mass的所有机器求值发生改变。密度积分和速度积分仍可见融合指令，故全局禁用FMA可能影响其他输出，本轮没有采用这种改法。

## 3. 同一输入下，差别确实能产生不同尾数

[arithmetic_probe.py](arithmetic_probe.py)只计算已有数据或明确构造的算术例子，没有执行任何LBM步骤或编译代码；结果见[arithmetic_probe.json](arithmetic_probe.json)。

### 3.1 明确标注的算术反例

使用rho=1、dx=5e-9、已舍入p=2.5000000000000004e-14，构造累计值M=3.5e-21kg。相同三个操作数下：

- 融合结果：3.625000000000001e-21kg（0x1.11e5b291d3cc1p-68）；
- 分开乘加：3.625e-21kg（0x1.11e5b291d3cc0p-68）；
- 两者相差1个双精度末位单位，绝对差7.52316384526264e-37kg。

融合结果另用精确有理数的乘加再一次舍入交叉核对。**该M为构造值，不是历史第28格或任何已观测的内部部分和；反例只证明两路径不保证逐位等价。** 不把这项算术计算当成复现了历史190个时间点。

### 3.2 已有最终密度切片的条件重建

读取P/T最终双精度XZ切片，按源码x外层/y中层/z内层顺序，在rho沿y不变的假设下延拓48层，计算57600项质量。新/旧切片字节相同。

| 条件重建结果 | P末步4342 | T末步2953 |

| 旧融合总质量（kg） | 7.199999999994686e-18 | 7.199999999999971e-18 |
| 新分开乘加总质量（kg） | 7.199999999994686e-18 | 7.199999999999971e-18 |

这说明相同输入可以在求和中途产生尾数差异，最后总量又相同。**这些是单次空间求和的“单元前缀”，不是时间步；沿y延拓是重建假设，未保存的全域双精度输入未被凭空补齐。** 它支持机器路径解释，但不是对190个历史差异点的直接再现。

## 4. 历史190点的归因仍缺什么

前轮完整对照保留：横槽mass与mass_error各190行不同、共380条，首次step11、最后2414、最大step1141；mass最大差7.395570986446986e-32kg，mass_error最大差1.0271626370072865e-14。两列是同一累计量及其派生值；新旧初始质量相同、相对变化分母定义相同。其余18个共同字段全程相同，全部保存输出和K对照也一致。

实际T保存场时刻为0,14,27,68,135,270,675,1350,2700,2953。**与190个质量差异时间点的交集为空。** 保存场还没有直接输出全域双精度rho/粒子分布，压力数组是有限精度导出；全局均值和极值也不足以恢复每格按顺序的密度输入。因此，当前绑定原始材料不能提供一次严格逐点、同输入对照的历史190点回放。

已查明的编译路径机制是目前有直接正证的解释；不能把它自动升级为“已排除所有其他未保存内部状态差别，且证明190点全部只由该机制引起”。同样，不能因本反例或量级小，为冻结回归规则临时创造新容差。
