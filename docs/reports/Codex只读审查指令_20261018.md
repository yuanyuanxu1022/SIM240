# 给 VS Code Codex 插件的只读审查指令（SIM240）

> 用法：VS Code 打开 SIM240 文件夹 → Codex 插件 → 新建一个任务 → 把下面整段贴进去。
> 模型：按项目 AGENTS.md §0.1 的建议，完整结果审查用 **GPT-6.1 Sol｜High**；若你界面里有 GPT-6 Astra，方法学审查可用 **Astra｜High**。
> 一个任务从头用到底，不要每轮换新任务。

---

把下面这段贴给 Codex：

```
你是本项目的独立审查人。审查 SIM240 第一篇论文的数据链、代码与思路。

【最高约束：这是只读审查任务】
- 不得修改、移动、重命名项目内任何文件；
- 不得编译、不得启动任何仿真、不得运行任何会写文件的原有脚本；
- 允许运行你自己写的只读复算脚本，临时文件只能放 /tmp；
- 结论直接输出在对话里，不要写入项目文件。
- 遵守项目 AGENTS.md 的输出纪律：区分「已验证 / 推测 / 下一步」，区分 NUMERICAL_GATE、RESULT_PASS、geometry_PASS 三类证据，不得互相替代。

【审查任务书】
完整背景、审查清单（五级优先）、已知弱点、输出格式，见
docs/reports/GPT独立审查指令_20261018.md 中「=== 复制开始 ===」至「=== 复制结束 ===」段。
该任务书原本写给拿不到文件的网页模型，其中"请作者提供文件"一律改为：你自己按路径直接读。

【你能直接读的关键路径】
- 原始结果（36 个主方向工况）：CASE/D_series/D2_groove_error_map/results/h*_d*_dx*_P 或 _T/steady/result.txt
- 加密工况：同目录下 h50_d100_dx2.5_* 与 h125_d25_dx2.5_*；黏度对照 mu15_h75_d100_dx5_*
- 证据表：docs/reports/SIM240_manuscript_revision_20261018/map36_evidence.csv
- 生成源码：CASE/D_series/D2_groove_error_map/src/d2_groove_error_map.cpp
- 拟合脚本：CASE/D_series/D2_groove_error_map/analysis_fit_v2.py
- 稿件：docs/reports/第一篇论文_第2章方法草稿_20261017.md、第3章验证、第4章结果、第5章对比对象选择（20261018）

【关于项目自审文档（重要）】
AGENTS.md 会引导你先读 SIM240_AI_CONTEXT.md 等状态文件。照读，但记住：
SIM240_AI_CONTEXT.md、CORE_CLAIMS.md、Chapter5_mechanism_audit_20261018/、
各类 *_audit / *_release / V2_FIT_REPORT **本身就是被审对象**，不是可信依据。
你的每一条判断都必须回到 result.txt / CSV / 源码自己复算，再与这些报告对照，
看报告说的是否属实。发现报告与原始数据不符时，如实指出。

【第一轮只做三件事】
1. 从若干个 result.txt 的 tau、dx_m、dt_s 反推实际运行的运动黏度与动力黏度，
   与稿件声称的物性核对，指出两者关系是否被写清楚。
2. 用 map36_evidence.csv 的 K_DNS_m3、K_model_m3 两列独立复算 E_pct，
   与表中 E_pct 列比对；抽 2 个工况回 result.txt 的 Keff_m3 验证 K_DNS 来源。
3. 审查源码中 effectiveK = muPhys * mainJ / (rhoPhys * acceleration) 的提取口径：
   J 是什么通量、除以什么、驱动是什么、有没有整体平移所有误差的风险。

完成后按任务书第 4 节的五节格式给出第一轮结论（无法判定的项如实写"证据不足"）。
未经我明确要求，不要进入第二轮，不要提出修改文件或跑新仿真。
```

---

## 给你的三个提醒（不用发给 Codex）

1. **它有权限改你的项目文件**——所以指令第一句就是"只读"。如果它中途提议"我帮你改一下 / 我跑个验证"，**先别同意，把它的提议原样贴回来给我看**。
2. 它读完第一轮结论后，你**整段复制回这个对话**给我，我逐条核实它的说法（它说某个数字不对，我能用原始文件当场验）。
3. 我和 Codex 的分工变了但闸门没变：**改文件、跑仿真、下结论进论文，仍然只从我这走**；Codex 只负责挑刺，挑得对不对由数据说话。
