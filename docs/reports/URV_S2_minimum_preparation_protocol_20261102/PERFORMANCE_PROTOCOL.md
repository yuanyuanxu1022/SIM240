# S2-MIP-v1-PERF：同一 ELF 的有限性能标定协议

状态：**仅协议；没有执行许可、实际编号或原生调用。** 目标是测出1.25 nm的实际短时吞吐量和资源使用，为正式执行资源决策提供证据。正式科学门槛和12小时时限均不改。

## 1. 固定条件与身份

只选 U_REG、dx1.25 nm、P→T 两条，各使用 ELF SHA `5c3836e97c99feab88cd8e41773237f6ff642a10558f151b11e112563382b07b`。h/d/w/P/Ly=60/80/120/240/240 nm，a1e5、nu1e-6、tau1、原 window_tstar=.75、max_time_H_diffusion=8、原帧计划全部保持。由六配置零步实读通过及封存无漂移作为前置条件。

实际执行必须另有明确覆盖“两条有限性能时间推进”的授权；若后续实施授权已明确包含，不重复索取同一许可。仅授权代码准备或零步不够。性能 release 采用独立 kind=AUTHORIZED_PERFORMANCE_RELEASE、purpose=S2_PERFORMANCE_NOT_REFERENCE、performance_time_stepping_authorized=true、formal_simulation_authorized=false，列两个性能 run_id、配置、绝对输出目录、来源闭包及外部SHA；这份 release 不进入正式 S2 binding。当前这些许可均为false、编号空。

未来目录限定在隔离 S2 树的 performance_runs 下，编号显式含 PERF；正式 runs、S1、S0及其他旧 CASE 为禁写区域。不能把性能编号列入 approved 的原 S2 planned_case 验收映射。

## 2. 同一程序的实际限制

该程序只有 describe/precheck/initialize/steady，没有专门测速或检查点恢复模式。steady 会写原生 formal_simulation=true，若输出该字段，保存原字节并在性能收据中解释用途。不能把它改成false来伪装成不推进。

保持原窗10368步和最大602112步，外部控制器在短预算内中止，不更改统计窗/收敛门/物理帧来追求速度。不新增内核计时、不重新编译、不用 LD_PRELOAD 或插桩改变运行路径。标定结束后的数据不可续跑、拼接或提升成正式参考；正式运行从新的初态、目录和合同开始。

## 3. 单条预算与中止

单条进程启动起墙钟上限1800秒；控制器一旦观察到完整diagnostics行的 step≥2048，或到达1800秒，以先到者为准发送SIGTERM；最多等10秒，再必要时SIGKILL。资源/来源/安全异常立即停止，并禁止自动执行T。这是性能观察预算，与原正式12小时上限不同；不能拿1800秒写入正式合同。

2048是**已落盘完整行的目标步**，不是实际 collideAndStream 调用数的硬上限。标准C++流缓冲和每秒观察使实际推进可能超过已见步数，须如实记录。若收到用户停止指令，立即保留现场并结束，不自动补测。

P出现意外退出、证据不足、资源越界、非有限值、原质量/密度/Mach/账本安全守卫违反或输入变化时 HOLD，不能自动进入T。观察预算用完但已经取得所需性能证据属于“计划中止并取得性能证据”，仍保留真实非零/信号退出及超时事实，不能报 native exit0 或数值PASS。

## 4. 观察方式与数据

控制器由用户后台启动后自动完成观察，AI不在交互任务内持续轮询。采用monotonic时间，每秒最多一次记录进程存活、完整诊断行的最新step、RSS、MemAvailable、输出字节和空闲磁盘。仅读取新增完整行；完整原始文件保留，末尾未换行片段单独标注，不悄悄删去或当完整记录解析。

吞吐量观察排除低于256步的热身。第一区间起点为首次观察到step≥256的样本，终点为此后首次观察到step≥起点step+512的样本；第二区间起点为首次step≥1024的样本，终点同样要求至少再增加512步。两个区间可以部分重叠，需如实说明。必须有正有限Δt，记录真实端点，而不是把名义256/768/1024/1536当作恰好采到的步数，也不能假设每一步都有精确时间戳。输出缓冲可能让行成批出现，时间分辨率和缓冲误差必须报告，不声称精确逐步耗时或1%测速精度。区间无法形成时标定为证据不足，禁止自动延长或重试。

保存：原配置/manifest、来源及库运行前后哈希、完整run.log/diagnostics及已有VTK、观察CSV、真实进程退出/信号/超时、开始/结束时间、父控制器停止原因、RSS峰值（标为观察峰值）、磁盘/输出轨迹、CPU/主机/解释器/线程环境。严禁伪造缺失result、原生execution_audit或最后一帧。信号结束可能不执行C++析构，原生调用计数可能缺失；最后完整诊断step只能作为推进下界，精确次数填null。

若意外出现完整原生末态或退出0，保存但不能自动报标定正常或转作参考；由于首次原完整窗口至少10367步，2048观察目标前不应正常收敛。应检查观察器是否失效或输出缓冲导致大幅超调，再决定性能证据是否可信。没有清楚原因时 HOLD。

## 5. 判读与后续决策

PERF_EVIDENCE_SUFFICIENT 只表示：两个所需时间区间完整、来源未变、资源和诊断安全守卫无异常、停止轨迹可解释；它不等于程序/几何/数值验收。其余记 PERF_EVIDENCE_INSUFFICIENT 或 PERF_ABORTED_UNEXPECTED，保存原因，不重试。两方向均应有相应证据，不能用P代表T。

按实际区间分别报告每步耗时与方向差。可用慢区间外推“若走满602112步”的条件计算成本，并另列初始化、输出开销未知；12小时除以慢区间耗时只得到粗略可推进步数。不能把外推当成预计收敛时间或保证完成。短段尚未覆盖完整10368步统计窗，窗口计算开销后续还会出现；长时间内存/缓存/IO变化也未被完整观察。

所有科学字段固定 NUMERICAL_GATE=NOT_EVALUATED、RESULT_PASS=false、REFERENCE_QUALIFIED_FOR_CASE=false、MODEL_COMPARISON/physical_validation=NOT_EVALUATED；只报告短时资源诊断，不评价V2。数据不得进入三网格GCI或模型误差表。

资源不足或12小时可行性仍不确定，应在正式运行前如实交付限制和可选范围；不自动加时、减少帧、改变网格或换机器。即便决定先跑粗/中格，也须另列部分执行范围并保持参考资格未满足。标定结束后不自动启动正式S2或S3。
