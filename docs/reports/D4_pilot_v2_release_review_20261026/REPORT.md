## 2. 运行前必须补齐的技术条件

### R1：独立读回没有连接“方程解”与“保存流场”

**观察：** P/readback.py:38–80 使用 algebraic_solution_before_backsub 重算残差，另外使用 reconstructed_solution 检查壁面、周期和压力均值；没有重算周期回填后向量是否来自同一个代数向量。

**实证：** 本轮复制旧人工5×5矩阵夹具，保持A、b和代数向量不变，仅将重建向量第0分量及对应速度数组从1改为7，并更新这两份数组的哈希。旧读回在修改前后均返回 DIAGNOSTIC_READBACK_PASS；该非从属分量与原向量差为6。副本保存在 `counterexample_work/`，原夹具未改。哈希重算是为了隔离“数值关系缺失”，不是声称普通文件损坏会绕过哈希。本反例只调用 check(work)，**没有冒充真实父进程记录通过**；真实分支额外检查单元坐标映射，同样没有向量重建关系检查，见 P/readback.py:123–143。

**影响：** 当前PASS不足以支持“所验流场就是所解方程的结果”；这属于独立验收缺口，不证明真实求解器已经产生错误。

**最小补救：** 在新版本读回中，依保存并核准的周期从属/主自由度及系数，独立构造重建向量：非从属分量保留x，从属分量按约束回填；逐分量比较r，再进行压力去均值。当前固定接口为一对一、单位系数（旧 interface.py:131–162 已有检查），应独立核保存配对/系数与该合同相符，不把规则扩展为未验证的通用多主约束。补“非从属值错”“从属回填错”“压力平移错”三类人工拒绝测试，沿用原诊断阈值并明确归一化口径。

**同属读回闭合的补项：** P/readback.py:99–143 未强制读取 solver_diagnostics.json、runtime_environment.json 和 stages.jsonl 的内容；文件清单只能证明已列出的文件未变，不能证明必需记录齐全。应固定真实成功记录必备集合，核KSP reason>0、配置/迭代上限、记录残差与独立残差一致、运行环境/来源/阶段/资源证据相符，缺失或矛盾拒绝。当前P/runner.py:92的CLI返回码也未显式纳入 inventory_error/supervisor_error，需避免记录失败却返回整体0；保留子进程独立退出码与记录阶段结果分别报告。此项为源码审查结论，本轮未伪造真实运行记录或声称已完成真实路径测试。

### R2：临时工作卷没有形成可持久保存的原始档案

**观察：** P/runner.py:24–63 将 stdout/stderr 和worker的全部原始输出保留在work；record只保存合同、来源、退出码与文件哈希等。P/worker.py:85–108 的矩阵、向量、流场、诊断和失败向量都在work下。没有将完整work复制到持久磁盘、独立读回副本后发布完成状态的步骤。

**影响：** 当前要求work位于tmpfs。Linux官方文档说明，卸载tmpfs会丢失其中内容；哈希清单不能恢复原始数据。[Linux tmpfs文档](https://docs.kernel.org/filesystems/tmpfs.html)（2026-10-26查阅）。这不是已有数据丢失事件：真实诊断尚未启动。

**最小补救：** 为成功、失败、超时和OOM四种终止情况增加同一持久归档阶段。先确认工作子进程树停止写入，再将全部已落盘文件（含部分文件和失败标记）复制到独立普通磁盘的新目录；前后逐文件大小/SHA一致，刷新文件与目录，再发布完成清单。复制/空间不足/刷新失败必须明确归档未完成，不清理源工作卷，不掩盖独立子进程退出码；不承诺保留OOM时尚在内存中的向量。

独立读回应支持“原始运行路径 + 持久副本路径”的显式绑定，只读持久副本也可验收，而不是篡改原合同work_dir来迁移记录。启动前核持久目标的实际挂载类型/身份及可用容量，不能仅凭两个路径不嵌套就称两卷独立。现有≥2GiB预算先保留，足以容纳≤512MiB单份原始卷及必要记录的条件须实际核对；不扩大为全18项预算。
