## 3. 量纲：不能把论文K改成h²/12

当前稿使用J=(1/Aplan)∫u dV、K=mu*J/G，单位分别m²/s与m³，平板K=h³/12。若用平均速度ubar=(1/Vfluid)∫u dV，则kappa=mu*ubar/G=nu*ubar/a，单位m²，平板kappa=h²/12。二者K=Href*kappa，Href=Vfluid/Aplan；等宽槽中Href=h+d/2，平板为h。单位宽流量是J=(G/mu)h³/12，不是单独的h³/12。

平板中同一h乘因子会抵消，因此两种正确对应归一化得到相同相对差；这不能证明沟槽的换算已经正确。后处理必须输出与论文一致的K_m3，并明确Vfluid与Aplan。原贴文“h²/12才是K，h³/12写错了”应撤回，保留“先前混用了K与kappa的记号”。

## 4. 当前骨架的两个具体问题

1. 当前网格将y方向设empty，checkMesh明确两求解方向为(1 0 1)，日志只解Ux/Uz。OpenFOAM13 fvMatrixSolve.C:136—143按validComponents跳过无效分量。因此不能将源向量改成y就称沿槽解；沿槽Uy(x,z)应独立解标量Poisson，或另外构造可求Uy且满足平移不变的周期挤出模型。只需在实现前定清，不自动新增物理任务。
2. incompressibleFluid/momentumPredictor.C:38保留fvm::div(phi,U)。日志“laminar stress model Stokes”只说明该应力模型名，不能证明已移除惯性对流。平板充分发展时对流不影响，故平板基准不能发现这一差别。正式参考需匹配Stokes方程或事前控制剩余惯性误差，不能仅据低Re口头判断已同方程。

固定贴体块网格的台阶可以正交，尖角本身不必导致非正交超限；仍要检查角点附近分辨率。现平板checkMesh全正交不证明未来槽网格合格。

本机源码定位：/opt/openfoam13/src/finiteVolume/fvMatrices/fvMatrix/fvMatrixSolve.C；/opt/openfoam13/applications/modules/incompressibleFluid/momentumPredictor.C。官方同版本源码亦核对：https://cpp.openfoam.org/v13/fvMatrixSolve_8C_source.html 。未运行求解器。
