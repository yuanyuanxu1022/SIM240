## 2. 挂载与目录布置的约束

后续经授权的环境准备应仅建立上述新路径：若目标已存在、有内容、已有不同挂载或为符号链接，先停下核对，不能覆盖、清空或改现有公共卷。无需改fstab或持久系统服务；新挂载点只服务这一个受控诊断。目录创建和挂载属于后续环境动作，本轮未执行。

拟定tmpfs选项为 `rw,exec,nosuid,nodev,size=512M,mode=0700,uid=1000,gid=1000`。`exec`是为了兼容缓存中生成库的可执行映射：本机DOLFINx的jit.py使用XDG_CACHE_HOME/fenics，FFCx的jit.py:421–437通过ExtensionFileLoader加载缓存扩展模块。若工作卷使用noexec，加载所需的可执行映射可能被内核拒绝。[Linux mmap手册](https://man7.org/linux/man-pages/man2/mmap.2.html) 说明no-exec挂载上的PROT_EXEC映射会触发EPERM。此处是代码/接口依据，尚未执行实际工作卷加载试验。

tmpfs容量限制按文件系统容量检查，不能用普通目录配合定时抽样替代。卸载会丢失临时数据，所以源文件只在持久副本独立验收后才允许另行讨论清理；本方案不含自动卸载或删除计算源数据。[Linux tmpfs官方文档](https://docs.kernel.org/filesystems/tmpfs.html)

当前既有memory/pids委派只读检查通过。未来运行子组仍按原合同设置memory.max=4GiB、swap.max=0、oom.group=1、pids.max=32；不更改其他应用组，也不把上轮64MiB人工OOM测试当成真实4GiB后端预算证明。

## 3. 无求解核查顺序与判据

|阶段|限定动作|验收要求与失败处置|
|---|---|---|
|A 静态路径核查|运行本目录precheck_layout.py，读取mountinfo/statvfs/目录权限及cgroup委派|工作路径必须恰为独立tmpfs挂载点、空、≤512MiB、可写且允许执行映射；记录为独立普通文件系统、≥2GiB；内存≥6GiB。实际目录缺失或任一条件不符即不放行。脚本只读，不挂载、不导入求解后端。|
|B 记录盘小文件核查|在新建的专用探针目录写一个≤1MiB已知内容文件，文件和目录刷新、重开重读核SHA|记录写入、刷新及读回一致；探针失败则保存错误并停止，不启动真实worker。|
|C 工作卷缓存兼容性|在单独探针目录编译并加载一个仅返回常数的微型共享库，固定单进程/短超时|不加载DOLFINx/PETSc、不建网、不组装、不解方程；确认cache路径与真实挂载选项兼容。若失败先审编译/加载日志，不绕过输出上限或改真实科学参数。此步骤是未来方案，本轮未编译。|
|D 容量边界与失败留档|仅在专门探针目录按固定1MiB块实际写入已知数据，最大尝试513MiB、≤60秒，期望空间耗尽；不用稀疏文件冒充占用|记录成功写入字节、余量、inode与ENOSPC，证实限制来自该新卷；失败时记录盘仍能写独立退出码。若超过上限未失败或错误类型不符，立即停止；只准移除本次明确列出的探针文件以恢复空卷，不能清空其他路径。|
|E 持久副本独立读回|固定人工成功/失败夹具在该真实卷上走记录与归档流程|复制全部已落盘文件，核SHA/大小和原run路径绑定；源探针不可用时仍可从archive读回。空间不足/复制/发布失败须未完成，子退出码不改；不产生真实计算PASS。|
|F 最终再核|删除已确认的探针文件后重做A，记录磁盘余量、挂载选项、设备号、空卷及未使用run_id|全部无求解环境核查闭合后才审单项运行许可；实际授权仍独立。任何探针都不调用runner的真实执行入口或生成批准合同。|
