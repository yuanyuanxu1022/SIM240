### 3.2 V2 沿槽项的 h 依赖残差（本轮最重要的负结果）

学生保留了一个负结果：沿槽 h75→h100 残差变化 **7.93 个百分点**，超过预登记 5 个百分点结构筛查门槛（`structural_pass_le_5points=false`）。

我把全部 37 个样点按 h 排开，看到的是这个：

**沿槽 Kyy，V2 残差随 h 单调漂移，并在 h≈75–100 之间变号：**

| h (nm) | V2 残差均值 | 范围 | n |

| 25 | +5.38% | +3.39 ～ +7.21 | 3 |

| 75 | +4.18% | +0.71 ～ +6.75 | 5 |

**横槽 Kxx 没有这个趋势**：h25 −18.7～−7.1 → h50 −6.9～+0.09 → h75 −2.5～+3.9 → h100 +4.39 → h125 −4.0～+4.2，散在零附近、非单调。

## 4. 我发现的三个问题

### 问题 A：正式 verdict 文件里的方向比偏差符号是反的（低危，但会误导审稿人）

| 文件 | A 偏差 | 口径 |
|---|---:|---|
| `.../results/closure_blindtest_verdict.json` | **+6.555** | `A_LB/A_V2 − 1`（反向分母） |
| `PAPER1_new_four_cases_acceptance_20261107/ratios.csv` | **−6.152** | `A_V2/A_LB − 1`（统一口径） |

我手工验算：A_LB = Kyy/Kxx = 1.654764e−22/9.914424e−23 = **1.669047**；A_V2 = 1.621209e−22/1.035011e−22 = **1.566369**；1.566369/1.669047 − 1 = **−6.152%**。

统一口径（公式相对数值，正值=高估）给出 −6.152%，是对的。`verdict.json` 那个 +6.555% 是旧检查器的反向分母。

学生**已经发现并解释了这件事**（07 README 第 53 行 + `ratios.csv` 的 `legacy_reversed_V2_bias_percent` 列），保留了原字节以便追溯。做法规范。

**但遗留风险**：`closure_blindtest_verdict.json` 是**判定文件**，审稿人或后人只看它会读到 +6.555%，且它的 `PASS` 字段是字符串 `"true"` 而不是布尔值。本轮结论不受影响（兜底判据 `A_primary_worse_abs_bias_percent=4.39% ≤ 10%` 恒通过），但这是个埋着的坑。

### 问题 B：预跑预测表不在快照里，盲测不可审计

`prediction_identity.json` 声明预测来源是 `PAPER1_bound_closure_review_20261105/proposed_geometry_scalar_checks.csv`。我在整个仓库里搜，**这个文件不存在**——`PAPER1_bound_closure_review_20261105/` 只有 `S4_grid_recomputed.csv` 一个文件。

这正是 `immutable_prerun_contract_recovered=false` 的实质。学生标注了「未取得」，诚实；但这意味着**「预测在前、测量在后」这件事目前只有元数据自述，没有可审计原件**。时间戳（预测表 mtime 11-05 22:43，运行 11-06 15:33）也不可信——`chronology.csv` 自己标了 `mutable_filesystem_metadata_not_trusted_timestamp`。

结论：`strict_blind_test_certified=false` 是**必须保留**的，不能因为数字好看就升格。

新包用 `07_.../文件清单.csv` + `package_manifest.json`（1,475 条），旧清单是 8,836 条。学生写了「新清单与旧 8,608 条清单分别维护」，没有合并。
