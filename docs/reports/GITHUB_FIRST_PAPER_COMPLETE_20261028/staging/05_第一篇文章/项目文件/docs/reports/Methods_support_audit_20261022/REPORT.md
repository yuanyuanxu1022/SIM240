## 三项需要收紧或补充的表述

### 1. 历史版本与编译信息的全覆盖承诺超出证据

位置：§2.1约81行，原文：“所用OpenLB版本的提交标识、编译配置与二进制哈希随每次运行的清单文件一并保存，可据以复现。”

实测52/52清单有binary_sha256，四组分别22/22/6/2项；52份清单均没有source_sha256、generated_source_sha256、openlb_commit、compiler、compile_flags字段。这里是对这52份指定清单的检查，不是断言全文件系统不存在任何构建资料。当前Makefile存在编译参数，但没有自动建立它与四组历史可执行文件的绑定。

日志中的5953d8a-dirty在当前Makefile中固定注入；当前本机OpenLB HEAD=882924a9cfc8dcdf82909e39530789cb6f5ebcc4，CITATION.cff自标1.9.0。二者不能被替换或拼成历史运行版本证明。

候选替换句：

> 现存运行清单保存了二进制哈希，参数、结果与日志可按支持资料索引定位；部分历史运行的源码、编译配置及OpenLB依赖版本绑定尚未完整核实，作为来源限制保留。

本轮按用户的定点修改范围未替换该句，将其作为已证实的支持资料覆盖问题交付。

### 2. “52次”应明确是地图与附加检查的统计范围

§2.4另外使用G4基准几何18份运行记录，§3使用历史平板/沟槽三网格。不能将52理解为所有被引用数值研究的总运行数，也不能把复用/归档的文件数简单相加当独立新运行数。

候选替换句：

> 主地图及D2/D3加密、黏度和斜向附加检查共52项运行；历史平板与三网格基准、周期复制与多力检查另列于支持资料，不计入该52项清单。

### 3. 线性检查和参数来源的支持范围需保持限定

本轮复现的多力检查在h75/d100、dx2.5nm，不能等同36个5nm地图样点均做了多力检验。建议§2.4最后一句收紧为“该基准几何在所检力范围内保持线性响应；不据此声称全部采样几何已分别完成多力检验”。这不意味着其他点必然非线性。

P/w的规则区设计来源已能定位，不应继续笼统说“完全没有来源”；但选参意图、加工后实际尺寸以及5nm历史成本依据未由本轮证明。设计版图数据和物理实测需分别表述。
